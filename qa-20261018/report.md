## 실제 진행 범위

## 수집 실패 문서의 별도 열람

자동 수집 실패 30개 문서를 공식 원문 경로로 재확인했습니다. 공식 웹 문서 22개, 실제 Chrome 렌더링 3개로 총 25개에서 본문을 열람했습니다. SoundCloud 개인정보처리방침, Quizlet, Canva 약관·개인정보처리방침, Noom의 5개 문서는 이 경로에서 본문 확인을 마치지 못했습니다. 제한을 우회하지 않았습니다.

열람 성공 25개를 모두 조항 검수 완료로 처리하지 않았습니다. 실제 요약과 대조한 항목만 확인일을 갱신했습니다. ArtStation은 본문에 과거 약관과 별도 개정 안내가 함께 있어 최신 적용 문서 확인이 더 필요합니다. 그 항목의 대조일은 바꾸지 않았습니다. 원시 열람 결과: `retrieval-review.json`.

지그재그는 실제 브라우저가 이동한 한국어 약관·개인정보처리방침 직링크로 교체했습니다. Craft는 페이지 로딩 후 렌더링된 공식 본문에서 조항과 하단 2025-11-10 수정일을 확인했습니다.

## 자동 비교와 오탐 검토

Netlify 공식 PDF에 실제 요청하여 파일 비교 기준 생성에 성공했습니다. PDF 응답 형식 확인과 파일 바이트 해시를 추가했습니다. PDF 텍스트의 의미를 자동 해석하는 기능은 아닙니다. PDF 주소가 HTML 오류 페이지를 반환하면 비교 성공으로 처리하지 않습니다.

기존 차이 감지 7개 URL을 같은 로컬 수집 환경에서 다시 요청했을 때는 10월 17일의 기준 본문과 해시가 모두 같았습니다. 반면 GitHub 실행 환경에서는 다른 해시를 관측했습니다. 실행 환경·지역·언어·화면 구성에 따른 응답 차이 가능성이 있으며, 약관 개정이 없었다거나 오탐이라고 확정하지 않았습니다. 실제 대조한 조항은 갱신했지만 해당 문서 전체의 자동 비교 대기 표시는 강제로 지우지 않았습니다. 로컬 재수집 기록: `changed-retrieval.json`.

이번 코드 반영 후 GitHub 자동 실행 39129796395는 성공했습니다. 관측은 동일 119개·차이 8개·수집 실패 27개·새 기준 3개이며 Netlify는 `pdf-bytes`로 기록됐습니다. 별도 열람 성공과 자동 수집 성공 수는 다릅니다. 이후 실행에 따라 이 수치는 달라집니다.

## 생성 입력과 검수 기록 보존

깨진 `audit-original-catalog-20261009.json`을 과거 원본으로 복원했다고 주장하지 않습니다. 현재 운영 데이터를 보존하여 `data/catalog.json`과 `data/catalog-audit.json`을 정본으로 만들고 `scripts/build-catalog.mjs`가 배포 JS와 홈 미리보기를 생성하도록 했습니다. `--check`는 데이터·미리보기 불일치 시 실패합니다.

잘린 과거 입력에 의존하던 4개 구형 실행 파일에는 명확한 중단 안내를 넣었습니다. 부분 복구한 과거 자료로 최신 검수 내용을 덮어쓰지 않도록 했습니다. GitHub 자동 실행도 생성 일치 검사와 기존 회귀 검사를 먼저 통과해야 수집을 진행합니다. 현재 정본이 과거 기록의 모든 유실 내용을 복원한다는 의미는 아닙니다.
